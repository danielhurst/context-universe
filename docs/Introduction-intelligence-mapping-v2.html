The product

The Context Universe — a living intelligence layer

Not a wiki or a search engine. A conversant, institutional memory: people interrogate it in natural language, add to it through structured pathways, and it learns from usage. It stays current from live sources and says when it doesn't know — so trust comes from transparency, not confidence.

Formally: the Context Universe is the machine-readable, queryable graph of your organisation's institutional knowledge — the implemented form of the Intelligence Layer. It holds nodes (concepts, rules, judgments, decisions, patterns) and edges (relationships, dependencies), tagged by domain (e.g. Strategy, Regulatory, Adviser Practice, Client) and type (rule, judgment, exception). At any time it has a coverage profile — which domains and work units are populated, how dense they are, and what is missing (gaps flagged for curation). That profile drives which agents can run.

🔍

People interrogate it

Natural language questions, answers grounded in organisational reality with citations. Not generic chatbot output — institutional memory with provenance.

➕

People add to it

Structured contribution pathways. Capture reasoning when decisions are made; flag gaps for curation; extract expert knowledge before they leave.

📈

It learns from usage

Every question reveals what people need. Every correction reveals what's wrong. Usage is the improvement signal.

✓✗

It knows what it doesn't know

When it can't answer confidently it says so and flags the gap. A system that admits uncertainty is more trustworthy than one that sounds plausible.

Agents from context. Agents (micro-skills, workflows, copilots) are spun out based on what's in the Universe — only domains that are populated and maintained can power an agent. The same platform might expose a compliance Q&A agent in one firm (where Regulatory context is dense) and a client-briefing agent in another (where Client and Practice context are dense). What you see and what you can run depends on what context exists; no empty agents.

How to use it: Onboarding — new joiners query how the org thinks and what's been decided. Decision support — leaders query similar past decisions and constraints. Compliance — teams query approved regulatory interpretations. Knowledge preservation — extract expert knowledge before departures. Cross-team intelligence — discover what others already know and have tried.

Human creation and governance

The Context Universe stays current and trusted because people add to it in structured ways and because ownership and review are explicit. Not a one-time build — a living layer with clear rules for who creates, who approves, and how gaps get resolved.

Creation

How content gets in

Structured contribution pathways so the right knowledge flows in without chaos. Senior leaders capture reasoning when they make significant decisions. Anyone can flag a gap when the system says "I don't know" or when they spot something missing. Experts leaving the organisation get a lightweight extraction so their knowledge is preserved before they go. Contribution is simple and bounded — not "document everything" but "add this decision," "flag this gap," "capture this before John leaves."

Governance

Who owns what, how it stays trusted

Ownership by domain or work unit — someone is accountable for each slice of the Context Universe. Review rhythms (e.g. quarterly) to refresh high-stakes nodes and retire outdated ones. Access controls and confidence scoring so sensitive or unvalidated context is used appropriately. Gap resolution: when the system flags "I don't know" or a user flags a gap, there is a clear path to curation (who decides, how it gets added, how it gets verified). Provenance on nodes so you can see where a rule or judgment came from and when it was last updated.

Outcome: The Context Universe is not a static deliverable. It is a governed asset — created and maintained by humans, with clear ownership, review, and gap-resolution so it stays accurate, current, and trustworthy.

Why Jumping Straight to Build Fails

The three failure modes
we design against

01

Context Poverty

Without mapping what the organisation actually knows, AI systems retrieve from the surface layer only. Outputs feel generic because they are — the system doesn't have access to the judgment, relationships, and tacit patterns that define genuine performance. Rework becomes the norm. Trust never builds.

02

Political Resistance

People who hold tacit knowledge resist contributing it to systems they don't trust, built without their input, that threaten their leverage. Without surfacing this dynamic in the mapping stage and designing around it in the architecture stage, the context layer never gets the signal it needs. The most valuable intelligence stays locked.

03

Compounding Bias

AI systems that retrieve historical judgment without understanding which of that judgment should be trusted create a feedback loop — institutional blind spots become load-bearing. Each correct decision obscures the systematic errors building underneath. The architecture stage designs against this from the start.
